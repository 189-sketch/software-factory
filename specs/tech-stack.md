## Deployment

- Distributed as the unscoped npm package `software-factory-cli` (current version `0.1.3`).
- `npm run build` produces `dist/factory/` (Node ESM) and `dist/panel/` (Vite bundle).
- `factory install <target> --mode local` writes the npm dependency, daemon wrapper, dotenv template, and service files into a target repository without copying source.
- `factory install <target> --mode cloud` additionally copies GitHub Actions workflow templates from `dist/factory/templates/github/workflows/` into the target's `.github/workflows/`.
- Two execution adapters are packaged: `local` (only with `FACTORY_TRUSTED_EXECUTION=1`) and `docker` (`FACTORY_DOCKER_IMAGE`); `vm` is selectable via `FACTORY_VM_COMMAND`.
- Models are addressed through Anthropic-compatible endpoints: `ANTHROPIC_BASE_URL`, `ANTHROPIC_MODEL`, `ANTHROPIC_AUTH_TOKEN` must match the upstream service; no hard-coded defaults.
- Smoke test on a fresh temp directory uses `FACTORY_MODEL_ADAPTER=echo` to validate the pipeline end-to-end without real credentials or network calls.

## Constraints & Non-Goals

### Constraints

- Node.js must be `>=22.19.0`; older runtimes are not supported.
- The factory runs as a single daemon per repository at any moment; two daemons or a daemon + GitHub Actions on the same repository must be mutually exclusive by configuration.
- Tool schemas must be registered alongside their implementation; missing or unknown tools cause startup pre-check failure rather than silent execution with empty params.
- All published packages must validate `FACTORY_AGENT_MODE=llm`; the historical `stub` mode has been removed and silently ignoring model config is no longer permitted.
- Secrets (`GH_TOKEN`, `ANTHROPIC_AUTH_TOKEN`, etc.) are read from shell environment, `.factory-daemon/.env`, machine-level Claude settings, or `gh auth token` fallback — never embedded in committed files.
- Implementation runs in worktrees bound to a recorded base commit; commit SHA, verification receipts, and reviewer findings must reference the same artifact revision or the merge is rejected.

### Non-Goals

- Replacing the model provider, the Harness SDK, or adding new long-running agents is out of scope for the current reliability upgrade.
- A microservice cluster, message bus, or generic DAG orchestration platform is not introduced; the daemon and worker pool remain the only runtime architecture.
- Automatic preemption and transparent failover across machines that do not share a control state is not supported; multi-master coordination is deferred to a future design.
- A fast-track path that bypasses spec generation for trivial requirements is intentionally excluded until stability thresholds are validated.
- The factory does not modify the target repository's ProjectV2 board configuration beyond issue status sync and label application.
