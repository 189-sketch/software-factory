## Files Changed

- `src/agents/triage.ts` (modified) — the readiness-gate path of `TriageAgent.run()` now runs A1 (freshness `Noul`) FIRST, then sends ONE `typesafe` batch carrying `{ A2: Choice×1 + Noul×1, A3: Noul×1, B12: Choice×1, B13: Score×1, B14: Noul×1 }` on a shared `JudgmentState`.
  New exports: `TriageCache` (orchestrator-threaded cache surface), `TriageBatchPrimitive`, `TriageTypesafeOutcome`, `TriageTypesafeError`.
  New private methods: `runReadinessGate()` (A1 resolution order + batch dispatch), `callFreshnessNoul()` (agent-side A1 typesafe call), `runTypesafeBatch()` (the 6-primitive POST), `runClaudeCodeFallback()` (the preserved legacy path).
  New module helpers: `loadDecisionsSafe()`, `triageStateFromPrimitiveValue()`, `mapTriagePrimitivesToResult()`, `formatNoul()`, `noulYesFromPrimitives()`, `numberFromPrimitives()`, `stringFromPrimitives()`.
  The existing `parseTriageDecision()` / `parseTriageRouting()` / `buildDecisionFromState()` / `TRIAGE_READINESS_CONTRACT` / `TRIAGE_SUPERVISOR_CONTRACT` / `TRIAGE_STATE_MESSAGES` / `heuristicDecision()` are ALL preserved verbatim as the fallback chain; the supervisor hat (`supervise()`) is untouched.
- `src/core/decision-router.ts` (new) — `applyDecision(action, payload, decisions)` + `decisionRouter` facade implementing Decision 5: tier resolution (escalate → auto → confirm) reads the `decisions.yaml` rows instead of hard-coded thresholds.
  Returns `{ mode: 'auto' | 'confirm' | 'escalate', target?, prompt? }`.
  Unknown actions return `{ mode: 'escalate', target: 'unknown_action' }`; a missing/NaN confidence on a confidence-gated action never routes to auto/confirm (no silent defaults).
  Gate semantics: a configured `confidence_min` / `noul_yes_max` requires a finite observed value; an unconfigured gate is vacuously true, so noul-only rules (`freshness.skip`) and confidence-only rules (`triage.apply_label`) both resolve.

  New imports: `buildJudgmentState` / `stateHashFor` (T8.2) and `type TriageCache`.
  The supervisor construction site (`triage-supervisor`) is untouched.
- `src/__tests__/triage-typesafe.test.ts` (new) — 17 unit tests covering the acceptance bullets (details below).

No file outside the task scope was modified: `src/core/agent-runtime.ts`, `runtime/agent-backends.mjs`, `runtime/typesafe-backend.mjs`, `scripts/factory-daemon.mjs`, `control-panel/`, and every other `src/agents/*.ts` are untouched.

## Deliverable

### A1 freshness resolution order (in `runReadinessGate`)

1. Deterministic fast path: `stateHashFor(buildJudgmentState(issue)) === cache.lastJudgmentHash` ⇒ return `cache.cachedTriage` verbatim with zero model calls (mirrors `freshness-poc.mjs`'s `state_unchanged` branch).
2. Upstream reuse: when the orchestrator already ran `freshnessCheck` (T8.4) this poll and threaded `cache.freshnessResult`, its `noul_yes` verdict is reused — `skip: true` returns the cached result, `skip: false` proceeds to the batch.
3. Agent-side A1: cached result exists + hash moved + no upstream verdict ⇒ the agent makes its own `typesafe` call carrying a single `Noul` primitive (`id: "A1.freshness"`) and routes the answer through `applyDecision('freshness.skip', { noul_yes }, decisions)` so the 0.20 threshold stays configurable in `decisions.yaml`.
   `mode: 'auto'` ⇒ reuse cache; anything else ⇒ full batch.
   A1 unavailable (network / key / off-toggle) ⇒ conservatively proceed to the full batch (`freshness_unavailable` posture from T8.4).
4. No cache at all (first sight) ⇒ straight to the batch.

### The batch (one POST)

`runTypesafeBatch` sends `{ model, state_hash: stateHashFor(state), primitives: [6 entries] }` via `runTypesafeStageFromConfig` (T8.1) with `action: 'triage.apply_label'` + `decisions` threaded so CJK fallback trigger 3 (per-action confidence gate) applies.
Primitive ids/types: `A2.triage_state` (Choice), `A2.author_committed` (Noul), `A3.author_binding_decision` (Noul), `B12.supervisor_action` (Choice), `B13.supervisor_complexity` (Score), `B14.needs_info_wakeup` (Noul) — all six carry the SAME `JudgmentState` instance (Decision 3: state is shared, not duplicated).
The response is mapped back into the existing `TriageResult` shape via `buildDecisionFromState` (label / remove_labels derived from state, exactly like `parse()` output), with the supervisor action + complexity landing on the same state's comment surface.
Routing: `applyDecision('triage.apply_label', { confidence: A2 confidence }, decisions)` ⇒ `{ mode: 'auto' }` (≥ 0.85) / `{ mode: 'confirm', prompt: 'Triage suggests: <state>. Apply?' }` (0.50–0.85) / `{ mode: 'escalate', target: 'needs-info' }` (< 0.50), per `runtime/decisions.yaml`.

### Fallback chain (preserved)

typesafe `failed` envelope (unreachable / 4xx / 5xx / missing key / off-toggle / non-JSON / empty primitives) ⇒ tagged `TriageTypesafeError` ⇒ `runClaudeCodeFallback()` which runs the ORIGINAL `dispatchAgentStage("triage", …)` call with the ORIGINAL `TRIAGE_READINESS_CONTRACT` + `parseTriageDecision` ⇒ on throw, `heuristicDecision()` (deterministic rubric).
No typesafe failure mode can hard-abort the readiness gate.

### Tests (`src/__tests__/triage-typesafe.test.ts`, 17 tests)

1. typesafe batch returns valid JSON → produces `TriageResult` with confidence surface; asserts ONE fetch, 64-char `state_hash`, and exactly the six primitive ids in one batch.
2. typesafe unreachable (mock fetch → 500) → synthetic fallback envelope surfaced (`typesafe_fallback_to_claude: http 500` in warn log) and the calling stage degrades gracefully to a valid `TriageResult`.
3. typesafe returns non-JSON (format-error) → falls back to the claude-code path.
4. decisionRouter: `confidence >= 0.85` → `{ mode: 'auto' }`.
5. decisionRouter: `0.50 <= confidence < 0.85` → `{ mode: 'confirm', prompt: … }`.
6. decisionRouter: `confidence < 0.50` → `{ mode: 'escalate', target: 'needs-info' }`.
7. decisionRouter: unknown action → `{ mode: 'escalate', target: 'unknown_action' }`.
8. `decisionRouter.apply` is an alias for `applyDecision`.
9. decisionRouter: `freshness.skip` noul_yes ≤ 0.20 → `{ mode: 'auto' }` (noul-only rule).
10. decisionRouter: `freshness.skip` noul_yes ≥ 0.20 → `{ mode: 'escalate', target: 'full_triage_batch' }` incl. the 0.20 boundary.
11. decisionRouter: missing confidence on a confidence-gated action never routes auto/confirm.
12. Cached triage reuse: second call within the same state hash returns the cached result WITHOUT any fetch (throwing mock proves it).
13. A1 Noul below threshold (hash moved, no upstream verdict) → ONE fetch carrying only `A1.freshness`, cached result reused, batch never runs.
14. A1 Noul above threshold → TWO fetches (A1 first, then the 6-primitive batch); the batch answer wins over the stale cache; ordering contract asserted.
15. Upstream `freshnessResult` (skip=true) reused → zero fetches.
16. A1 unavailable (500) → conservatively proceeds to the full batch (2 attempts), stale cache NOT reused.
17. Sanity: `loadDecisionsSync()` on the shipped `runtime/decisions.yaml` routes 0.92 → auto and 0.30 → escalate/needs-info.

## Notes for Reviewers

- The A1 agent-side call reads the `Noul` answer from the response's `confidence` channel, mirroring `freshness-poc.mjs::callTypesafeNoul` (T8.4) so both A1 implementations agree on the wire convention.
- The `freshness.skip` boundary (noul_yes == 0.20) resolves to escalate/full-batch because `escalate` is checked first — conservative and pinned by test 10.
- `loadDecisionsSafe()` re-reads `runtime/decisions.yaml` only when the constructor did not inject the parsed file; a read failure degrades to `unknown_action` escalate routing instead of crashing (no silent defaults, no hard aborts).
- The orchestrator change is strictly additive: two construction sites gained a third constructor argument, one private helper was added, and `lastJudgmentHash` (an existing optional T8.4 field) is now stamped after triage.
  Checkpoints written by older versions load unchanged.
- Production behaviour today: `FACTORY_AGENT_BACKEND` defaults to `claude-code` and `TYPESAFE_API_KEY` is typically unset, so the batch short-circuits to `no-api-key` and the fallback runs the exact legacy path — the migration is behaviour-preserving until an operator enables typesafe.
- Pre-existing, out-of-scope observation: `npm run test:cli` emits a Node `DEP0190` DeprecationWarning (child-process `shell: true` in the CLI package test harness).
  It predates this task, does not affect any exit code, and the harness file is outside T9.0 scope.
