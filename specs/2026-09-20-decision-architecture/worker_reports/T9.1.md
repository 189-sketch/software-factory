## Design notes

1. **Gate on backend selection.** The typesafe batch is attempted only when the runtime resolves the role to `typesafe` (default backend or per-role override). Without this gate, every claude-code deployment with no `TYPESAFE_API_KEY` would receive synthetic REJECT/blocked shapes — a production regression. Asserted by the two "claude-code deployment" no-regression tests.
2. **Fallback semantics per task spec.** format-error / parse miss → claude-code via `dispatchAgentStage` (forced through `claudeFallbackRuntime`); typesafe unreachable / 5xx / OFF / missing key (CJK fallback envelope) → synthetic typed shape, never an implicit claude re-run (`retryable: false` contract).
3. **`normalizeConfidence` does not clamp.** Out-of-range values (`<0`, `>1`, NaN, undefined) collapse to `0` → escalate. Clamping `1.5 → 1.0` would have routed a buggy answer into the `auto` tier (`1.0 ≥ 0.90`).
4. **Boundary tie-break.** At `confidence == 0.65` both `escalate.confidence_max` and `confirm.confidence_min` match; escalate is evaluated first (conservative). Documented in the router and pinned by a test.
5. **Test hygiene.** Fallback tests point `FACTORY_CLAUDE_COMMAND` at a missing binary so the claude-code dispatch fails fast (spawn ENOENT) instead of spawning the real CLI — the earlier 120 s hang is gone (full unit suite now ~3.6 s).
