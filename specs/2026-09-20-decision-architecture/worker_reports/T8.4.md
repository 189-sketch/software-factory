## Deliverable

`scripts/freshness-poc.mjs` exports:

- `buildJudgmentState(issue, ctx?, opts?)` — mirrors `src/core/judgment-state.ts::buildJudgmentState` line-for-line. Lazily populates `issue / factory / repoSignals`, defaults `failureCounts: {}` + `priorDecisions: []`, only writes `lastTriageAt` / `lastJudgmentHash` / `lastReceiptRegistry` when the caller supplies them. Uses the same factory-comment detector markers (`<!-- pi-software-factory:triage:` / `spec-review:` / `pr-review:`) as `src/core/factory-comments.ts`.
- `stateHashFor(state)` — implements the spec's SHA-256 formula: `sha256(updatedAt | '|' | comments.length | '|' | lastReceiptSha | '|' | lastTriageAt | '|' | labels.join(','))`, where `lastReceiptSha = sha256(JSON.stringify(lastReceiptRegistry))` when the registry is present or `''` when absent. Cross-checked against the TS reference in the unit test.
- `freshnessCheck(issue, options)` — main entry point. Algorithm:
  1. Load `<stateDir>/issues/<n>.json` (returns `null` when absent).
  2. Build the `JudgmentState` from `issue` + the checkpoint's `lastTriageAt` / `failureCounts` / `priorDecisions` / `lastReceiptRegistry`.
  3. Compute `stateHash` via `stateHashFor`.
  4. **Fast path:** when `stateHash === checkpoint.lastJudgmentHash` return `{ skip: true, reason: 'state_unchanged', stateHash, noul_yes: 0 }` — no `typesafe` call is made.
  5. **No-cached-hash:** when the checkpoint has no `lastJudgmentHash`, persist the new hash and return `{ skip: false, reason: 'no_cached_hash', stateHash, noul_yes: 0 }`. The daemon proceeds to enqueue (full triage on first sight); `judgment.skip` is NOT logged because there is no skip.
  6. **`FACTORY_TYPESAFE_OFF=1`:** persist the new hash and return `{ skip: false, reason: 'freshness_unavailable', stateHash, noul_yes: 0 }` (no outbound HTTP).
  7. **Missing `TYPESAFE_API_KEY`:** persist the new hash and return `freshness_unavailable` (no outbound HTTP).
  8. **`typesafe` Noul call:** build the request envelope from `runTypesafeStageFromConfig`'s contract, run it via the existing T8.1 adapter (which handles every failure mode internally), extract `noul_yes` from the `freshness` primitive's `confidence`. On `failed` result → `freshness_unavailable`. On `noul_yes < threshold` → skip with `reason: 'state_unchanged'`. Otherwise → `skip: false, reason: 'state_changed'`.
  9. The new `stateHash` is persisted on the checkpoint on EVERY successful check (both skip and no-skip paths), so a subsequent poll can short-circuit on the matching hash. `persistLastJudgmentHash` is best-effort: a missing checkpoint file is a silent no-op (the next real save path will create it).
- `computeHealthJs(scores, weights?)` — inlined JS port of `src/orchestrator/composite.ts::computeHealth`. `clamp(sum(weight_i * score_i) / weightSum, 0, 1)`. Defaults to T8.3's shipped weights (`spec: 0.30 / impl: 0.25 / review: 0.20 / verify: 0.25`) when `weights` is omitted. Throws on missing / non-finite scores / weights; clamps out-of-range scores to `[0, 1]` (Phase A's silent-default ban is preserved).
- `summariseFreshness(outcomes)` — reduces per-issue outcomes to the `{ checked, skipped, fresh, unavailable, skippedRate }` shape the `daemon-tick` log consumes. Empty array → `DEFAULT_FRESHNESS_STATS` (all zeros).

`scripts/freshness-poc.d.mts` mirrors the JS surface verbatim so `npm run typecheck` accepts `import { ... } from "../../scripts/freshness-poc.mjs";` under `strict`. No `any` escape hatches in the test.

`scripts/factory-daemon.mjs` modifications:

- New `FRESHNESS_NOUTH_YES_MAX` startup constant, loaded once via `loadFreshnessNoulYesMax()` from `runtime/decisions.yaml`. Looks at two candidate paths (`factoryRoot/runtime/decisions.yaml` then `process.cwd()/runtime/decisions.yaml`); extracts `decisions.freshness.skip.auto.noul_yes_max` with a regex tailored to the spec's flow-mapping format. Falls back to `0.20` (the spec's documented default) on any parse / range error.
- `daemon-start` log line now includes `freshnessNoulYesMax` so operators can confirm the loaded threshold at boot.
- Inner pick-up loop inserts `freshnessCheck(issue, { stateDir: STATE_DIR, threshold: FRESHNESS_NOUTH_YES_MAX, env: process.env, fetchImpl: globalThis.fetch })` between the lease-cooldown guard and the `readyIssues.push(issue)` call. On `skip: true` the loop logs `INFO judgment.skip { issue, reason, stateHash, noul_yes, threshold }` and `continue`s. The wrapped `try/catch` around `freshnessCheck` ensures an unexpected throw (the module's contract is "never throws", but a future bug should not crash the daemon) maps to `freshness_unavailable` + the existing enqueue path.
- `freshnessOutcomes[]` is aggregated per cycle; after the inner loop, `summariseFreshness(freshnessOutcomes)` + `computeHealthJs` produces the composite `health` (skip-rate is the Phase B MVP proxy for all four dimensions). The `daemon-tick` log line is emitted exactly once per cycle iteration and carries `fetched / skipped / fresh / unavailable / skippedRate / health / threshold`. Errors in `computeHealthJs` are non-fatal — the daemon logs `healthError` and falls back to `health: 0.5` so the tick log still records a numeric value.
- The existing `process-issue-start` / `process-issue-end` lifecycle for non-skipped issues is preserved unchanged: skipped issues simply never enter the lifecycle.

## Notes for Reviewers

- The freshness module is a pure-JS file because `scripts/factory-daemon.mjs` is launched with `process.execPath` from `bin/factory.js` and does not have a TypeScript runtime. The SHA-256 hash + `JudgmentState` builder are inlined here; the TS reference at `src/core/judgment-state.ts` remains the canonical source. Unit test 1 cross-checks parity so the two implementations cannot drift silently.
- `computeHealthJs` is also a JS port of `src/orchestrator/composite.ts::computeHealth` for the same reason — the polling loop's `daemon-tick` log needs the composite health but the daemon has no TS runtime. The JS version uses the same weights, the same clamp + `weightSum` normalisation, and the same throw-on-missing-scores behaviour. Unit tests 12–16 prove the formula is intact.
- The freshness module's `no_cached_hash` reason is intentionally distinct from `state_unchanged` / `state_changed`: it is the "first sight" path on a brand-new issue where the cached hash has not been written yet. Logging `judgment.skip` here would be misleading (there was no cached judgment to skip), and `persistLastJudgmentHash` already seeds the next poll's hash so the following tick short-circuits.
- The polling loop's `freshnessOutcomes[]` is aggregated per cycle; the `daemon-tick` log line is emitted exactly once per cycle iteration, satisfying the "computed once per cycle" requirement. The Phase B MVP feeds skip-rate as the proxy for all four dimensions; later tasks (T9.x) will replace this with the underlying per-dimension scores.
- `lastJudgmentHash` + `lastTriageAt` on `FactoryIssueState` are optional additive fields. Older checkpoints without the field load unchanged (JSON parses as `undefined`); the freshness module treats undefined as "no cached hash" and proceeds to the `no_cached_hash` path. No migration step is required.
- The smoke test (`test/freshness-poc-cli.test.mjs`) uses `--once` to bound wall-clock to ~1 s rather than the full 60 s from plan.md R7 — the daemon exits after one cycle whether the issue processes successfully or not, and the `process-issue-start` log is emitted BEFORE the worker spawn (so the assertion holds even though the worker would later fail at the LLM-stub layer).
