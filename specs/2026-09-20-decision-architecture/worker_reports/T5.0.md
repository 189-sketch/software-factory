## Verification

`requirements.md` §"CJK Fallback Contract" enumerates:

1. **Three trigger conditions**:
   - `POST https://api.typesafe.ai/v1/systemone` returns 4xx/5xx or times out.
   - `TYPESAFE_API_KEY` is missing or invalid.
   - Per-action `confidence` falls below `decisions.yaml[<action>].escalate.confidence_max`.

2. **Three behaviour clauses**:
   - Adapter returns `StageRunResult` with `status: 'failed'`, `warnings: ['typesafe_fallback_to_claude: <reason>']`, `retryable: false`.
   - Orchestrator surfaces as graceful degradation event (NOT hard abort).
   - Until Phase 11 Slice F (`FACTORY_AGENT_BACKEND_FALLBACK` opt-in) lands, no auto-re-run on Claude; calling stage reports the fallback in its summary.

3. **Four observability clauses**:
   - `panel-read-model.mjs` shows fallback badge per stage.
   - Composite health signal downgrades any dimension whose source primitive ran on fallback.
   - Structured log fields: `fallback.reason`, `fallback.from_backend=typesafe`, `fallback.to_backend=claude-code`.

4. **Phase B test contract**:
   - `src/__tests__/typesafe-fallback.test.ts` covers all three trigger conditions.
   - `test/typesafe-fallback-cli.test.mjs` confirms `FACTORY_TYPESAFE_OFF=1` forces fallback regardless of API health.
