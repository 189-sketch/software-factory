`src/core/decisions.ts` exports:

- `READ_ONLY_ACTIONS: ReadonlySet<string>` — the closed set with the five example actions.
- `DecisionTierRule`, `DecisionRule`, `CompositeWeights`, `CjkFallbackBlock`, `FallbackBlock`, `DecisionsFile` — typed surfaces mirroring §"`decisions.yaml` Schema` line-for-line.
- `DEFAULT_DECISIONS_PATH = path.resolve("runtime", "decisions.yaml")` — the default file location relative to `process.cwd()`.
- `parseDecisionsYaml(raw)` — tiny in-tree YAML 1.2 parser for the exact subset the spec mandates (top-level `key: value`, sequences with `- key: value` + sub-rows, flow mappings `{ k: v }`, flow sequences `[ a, b ]`, comments, blank lines; CRLF-tolerant). No new dependency added; `js-yaml` is not in `package.json` and was not installed.
- `parseScalar` / `parseFlowMapping` / `parseFlowSequence` — exported helpers, individually testable.
- `loadDecisions(path?)` / `loadDecisionsSync(path?)` — file-system readers (async + sync).
- `validateDecisions(decisions)` — enforces all four schema rules from `requirements.md` §"Schema validation rules": (1) every `action` is in `READ_ONLY_ACTIONS`; (2) `confidence_min <= confidence_max` per action; (3) `composite.*` weights sum to `1.0 ± 0.01`; (4) unknown keys at every level (top / decision rule / tier / composite / fallback / cjk / typesafe_confidence_below) are rejected. Returns `{ ok: true } | { ok: false; errors: string[] }` with one human-readable error per failed rule.
- `runDecisionsPreCheck(path?)` / `runDecisionsPreCheckSync(path?)` — call `loadDecisions` → `validateDecisions`; on error throw `new Error('Invalid decisions.yaml: …')` (same severity / throw style / message key prefix as `Invalid FACTORY_AGENT backend: …` in `runtime/agent-backends.mjs::resolveAgentConfig` and the F01 `load_skill` regression). Returns the parsed file on success so callers can cache the weights without re-parsing.

`src/orchestrator/composite.ts` exports:

- `type Dimension = 'spec' | 'impl' | 'review' | 'verify'`
- `type DimensionScores = Record<Dimension, number>`
- `type HealthBand = 'alert' | 'banner' | 'log_only'`
- `primeDefaultWeights(decisions)` / `__clearDefaultWeightsCacheForTest` — module-private default-weight cache plumbing.
- `computeHealth(scores, weights?)` — returns `clamp(sum(weight_i * score_i) / weight_sum, 0, 1)`. Explicit `weights` overrides the lazily-loaded defaults; missing or non-finite scores throw (silent defaults never hide wiring bugs); out-of-range scores clamp to `[0, 1]`.
- `healthBand(score)` — `< 0.5 → 'alert'`, `[0.5, 0.7] → 'banner'`, `> 0.7 → 'log_only'` per Decision 6 / §"Composite Scoring Rubric"; non-finite input throws.
- `computeHealthFromDecisions(scores)` — async wrapper that lazily primes the default-weight cache from `decisions.yaml` then calls `computeHealth`.

## Notes for Reviewers

- `js-yaml` was deliberately NOT added to `package.json`. The spec's schema is small and well-bounded (top-level mapping + a single sequence of mappings + flow mappings inside each tier), so a 200-line in-tree parser covers it cleanly. Adding a dependency would inflate the install surface for no behavioural gain. The parser handles the exact subset the schema needs and is CRLF-tolerant (`/\r?\n/`) so Windows installs work end-to-end.
- `runDecisionsPreCheckSync` is the sync companion to the async `runDecisionsPreCheck`. The orchestrator's constructor body is synchronous (matching `SkillLoader` / `IssueStore` instantiation); the sync helper fires the pre-check at construction time. The async helper remains the canonical entry point for callers with an async setup hook (Phase B's T8.4 / T8.5 will use it).
- The `computeHealth` formula normalises by `weightSum` (rather than hard-coded 1.0), so a future operator override that re-weights above or below 1.0 still produces a value in `[0, 1]` rather than over- or under-shooting the band cutovers. This matches the spec's "operators can retune weights without code changes" requirement without changing the contract.
- The orchestrator constructor change is minimal: one new import line, one `runDecisionsPreCheckSync()` + `primeDefaultWeights(decisions)` call after the existing resource setup. No existing constructor body, method, or call site was modified. Existing test suites (`npm test`: 287 src + 108 fast + 7 contract; `npm run test:cli`: full packed-CLI smoke) continue to pass without modification.
- `src/orchestrator/composite.ts` is exported independently of `decisions.ts`, so later tasks (T10.0 control-panel health badge) can import `computeHealth` / `healthBand` without pulling the loader / validator surface.
