## Files Changed

- `src/agents/spec.ts` (modified)
  - `SpecAgent` constructor gains an optional third parameter `runtimeOverride?: AgentRuntime`, threaded into both `dispatchAgentStage` calls (spec-product / spec-tech). Production callers (`new SpecAgent(specCtx, attemptRevision)`) are unaffected; the seam lets unit tests inject a fake runtime instead of spawning a real CLI.
  - `SpecAgent.run()` now builds ONE `JudgmentState` (via `buildSpecJudgmentState`, `specBody` populated from the candidate PRODUCT.md body, or the previous attempt's body when revising) and sends ONE `typesafe` batch (`trySpecTypesafeBatch`) carrying `{ B1: Choice, B2-AC-*: Score × N, B3-AC-*: Noul × N }` — `1 + 2N` primitives in a single `POST /v1/systemone`, never N round-trips. On success the response is mapped into `SpecPair.confidence` + `SpecPair.typesafeBatch`.
  - The existing `PRODUCT_CONTRACT` / `TECH_CONTRACT` + `parseProductSpec` / `parseTechSpec` (`OutputContract` parsers) are UNCHANGED and remain the narrative/fallback path: any typesafe failure (`format-error` envelope, network / 4xx / 5xx, missing B1, malformed response) returns `null` from `trySpecTypesafeBatch` and the SpecPair from the claude-code `parse()` path is returned unenriched (no throw, no behaviour change for the orchestrator).
  - New exported helpers: `buildSpecJudgmentState`, `buildSpecTypesafeRequest`, `parseSpecTypesafeAnswer`.
- `src/agents/review-spec.ts` (modified)
  - `ReviewSpecAgent` constructor gains an optional second parameter `runtimeOverride?: AgentRuntime`, threaded into the `dispatchAgentStage` call. Production caller (`new ReviewSpecAgent(reviewCtx)`) unaffected.
  - `ReviewSpecAgent.run()` now builds ONE `JudgmentState` (via `buildReviewSpecJudgmentState`, `specBody` populated from the reviewed spec body) and sends ONE `typesafe` batch (`tryReviewSpecTypesafeBatch`) carrying `{ B4: Choice (verdict), B5-<findingId>: Choice × M (per-finding severity) }` — `1 + M` primitives in a single request. On success the response is mapped into `SpecReviewResult.confidence` + `SpecReviewResult.typesafeBatch`.
  - `REVIEW_SPEC_CONTRACT` + `parseSpecReviewResult` are UNCHANGED and remain the fallback path on any typesafe failure mode.
  - New exported helpers: `buildReviewSpecJudgmentState`, `buildReviewSpecTypesafeRequest`, `parseReviewSpecTypesafeAnswer`.
- `src/core/types.ts` (modified — additive only)
  - `SpecPair` gains optional `confidence?: number` and `typesafeBatch?: SpecTypesafeBatchAnswer`.
  - `SpecReviewResult` gains optional `confidence?: number` and `typesafeBatch?: ReviewSpecTypesafeBatchAnswer`.
  - New interfaces `SpecTypesafeBatchAnswer` (B1/B2/B3 buckets + `meanConfidence`) and `ReviewSpecTypesafeBatchAnswer` (B4/B5 buckets + `meanConfidence`). All fields optional on the carriers, so every existing consumer / checkpoint reader keeps working.
- `src/__tests__/spec-typesafe.test.ts` (new) — 11 unit tests.
- `src/__tests__/review-spec-typesafe.test.ts` (new) — 9 unit tests.

NOT touched (hard constraints): `src/core/agent-runtime.ts`, `runtime/agent-backends.mjs`, `scripts/factory-daemon.mjs`, `control-panel/`, `src/agents/triage.ts`, `src/agents/review-pr.ts`, `src/agents/verify-behavior.ts`. `READ_ONLY_ROLES` not widened. No new dependencies.

## Acceptance Mapping

- **"`src/agents/spec.ts` runs B1 (`Choice` PRODUCT vs PRODUCT+TECH), B2 (`Score × N ACs`), B3 (`Noul × N ACs`) on a shared `JudgmentState`"** → `trySpecTypesafeBatch` + `buildSpecJudgmentState` + `buildSpecTypesafeRequest`; one state instance is attached to every primitive (`assert.deepEqual(primitive.state, state)` in tests).
