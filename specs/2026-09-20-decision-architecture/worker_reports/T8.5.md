### `runtime/typesafe-backend.mjs` extension

```js
function findDecisionRule(decisions, action) { /* closed-set lookup */ }

export async function runTypesafeStageFromConfig(config, executable, request, opts = {}) {
    // ... existing branches (FACTORY_TYPESAFE_OFF=1, missing key, network, 4xx/5xx) ...

    // CJK fallback trigger 3 — per-action confidence below the
    // `decisions.yaml[<action>].escalate.confidence_max` threshold.
    if (primitives.length > 0) {
        const rule = findDecisionRule(opts.decisions, opts.action);
        const threshold = rule?.escalate?.confidence_max;
        const head = primitives[0];
        if (
            typeof threshold === "number"
            && head && typeof head === "object"
            && typeof head.confidence === "number"
            && head.confidence < threshold
        ) {
            return fallbackResult(
                `confidence ${head.confidence} below ${threshold} for ${opts.action}`,
            );
        }
    }
    // ... existing success path ...
}
```

The check is opt-in: when `opts.action` or `opts.decisions` is missing, the adapter behaves exactly like T8.1. The dispatcher / orchestrator owns loading `decisions.yaml` (Phase C / T9.x wires the call sites).

### `src/__tests__/typesafe-fallback.test.ts`

16 tests organised in four sections:

1. **Trigger 1 (5 tests)** — HTTP 401, HTTP 500, network error, timeout, non-JSON body. Each asserts the fallback envelope (`status: "failed"`, `retryable: false`, `providerSessionId: null`, `backend: "typesafe"`, `warnings[0]` matches `typesafe_fallback_to_claude: <reason>`).
2. **Trigger 2 (2 tests)** — missing `TYPESAFE_API_KEY` short-circuits before any HTTP; whitespace-only key is treated as missing.
3. **Trigger 3 (4 tests)** — confidence below threshold fires fallback; at-or-above threshold succeeds; missing `opts.action` is back-compatible with T8.1; unknown action is defensive (no crash, no fallback).
4. **Cross-cutting (5 tests)** — every path emits the structured log fields (`backend: "typesafe"` + `warnings[0]` carries the canonical `typesafe_fallback_to_claude:` prefix); `retryable: false` is asserted on five different failure scenarios across all three triggers.

### `test/typesafe-fallback-cli.test.mjs`

6 tests using Node's native `node:test` module:

1. `FACTORY_TYPESAFE_OFF=1` short-circuits before any HTTP — `fetchImpl` spy shows zero calls.
2. Missing `TYPESAFE_API_KEY` short-circuits before any HTTP — spy shows zero calls.
3. Whitespace-only `TYPESAFE_API_KEY` is treated as missing — spy shows zero calls.
4. Local `node:http` server returning HTTP 500 — adapter reaches the network and maps the upstream status to `typesafe_fallback_to_claude: http 500`.

6. Regression: the envelope shape (`status`, `backend`, `retryable`, `providerSessionId`, `warnings[0]`) is byte-identical to the unit-test runner's envelope.

The CLI runner imports `runTypesafeStageFromConfig` directly from `runtime/typesafe-backend.mjs` (same module the unit test uses) — a regression in the adapter fails both suites.

## Notes for Reviewers

- **Why the adapter was touched.** The current T8.1 implementation does not check `primitives[0].confidence` against `decisions.yaml`. T8.5's acceptance requires that trigger 3 return the same synthetic fallback envelope as triggers 1 and 2. The minimal change is two lines of confidence-comparison logic, gated on `opts.action` + `opts.decisions` so T8.1 callers stay byte-equivalent. The orchestrator's `decisionRouter` (Phase C / T9.x) wires both opts in.
- **Why `opts.decisions: unknown` (not typed).** `runtime/typesafe-backend.d.mts` imports types from `../src/core/*` (a TypeScript module). A typed `DecisionsFile` reference would create a runtime cycle / require dist artifacts. The duck-typed `unknown` is documented in the JSDoc; `findDecisionRule()` does the closed-set membership + threshold-typed check internally so a malformed input cannot crash the adapter.
- **Why the CLI test redirects via `127.0.0.1:port` rewrite.** `runtime/typesafe-backend.mjs` hard-codes `https://api.typesafe.ai/v1/systemone` as the endpoint; the test cannot change that without modifying the adapter. The local server rewrites the URL at the `fetchImpl` seam — the same seam tests already use for HTTP-mocking. The server side sees a real HTTP request from Node's `globalThis.fetch`, so the contract is exercised end-to-end without DNS resolution.
- **Why the mermaid diagram lives in §5.5.** `docs/harness-architecture.md` is a Chinese-language document; §5 follows the same style as §4 (mixed Chinese / English with the technical diagrams in ASCII / mermaid). The diagram is intentionally small (`subgraph`s + edges only) so it renders in both GitHub and most static-site renderers without external plugins.
- **Why `FACTORY_TYPESAFE_OFF=1` stays the canonical offline toggle.** T8.1's contract says the toggle short-circuits the adapter regardless of API health; the new tests verify that promise end-to-end. The CLI test (Test 1) directly imports the adapter and exercises the production path — no factory orchestration overhead.
- **No auto-retry contract.** `retryable: false` is asserted on five different failure scenarios across all three triggers. Until Phase 11 Slice F (`FACTORY_AGENT_BACKEND_FALLBACK` opt-in) lands, the orchestrator does NOT auto-re-run on Claude; the CJK fallback surfaces in the calling stage's summary.
- **`agentWorkerEnvironment` secret-leak guard.** T8.5's CLI tests do not mutate `process.env`; they inject `opts.env` so the `agent-backends.mjs` credential whitelist walk is exercised exactly the same way as production (per T8.0 / commit `48cdd0e`). The `agent-backends-environment.test.mjs` H-1 test still passes end-to-end.
