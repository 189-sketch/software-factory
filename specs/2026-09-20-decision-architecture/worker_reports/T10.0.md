## Read-model contract (what the panel sees per issue)

- `health: number | null` — `round2(computeHealthJs(scores, adjustedWeights))`; `null` until the orchestrator persists all four dimension scores on `document.scores = { spec, impl, review, verify }` (forward-compatible field; never invented).
- `healthBand: 'alert' | 'banner' | 'log_only' | null` — Decision 6 rubric (`<0.5`, `0.5–0.7`, `>0.7`).
- `stageConfidence: Record<stage, { runId, confidence }>` — from persisted judgment records only: `specs.confidence` (B1–B3 mean, T9.2) / `specReview.confidence` (B4–B5 mean) for the spec UI stage; forward-compatible `triage.confidence`, `implementation.confidence`, `review.confidence`, `implementation.behaviorVerification.confidence`; `runId` from the stage record else the stage's latest event; `confidence: null` when unpersisted.
- `fallbackBadges: Record<stage, { reason, at }>` — set when the stage's LAST run carried the contractual `typesafe_fallback_to_claude` marker: stage record `fallback:{reason,at}` / `warnings[]`, else the stage's most-recent event `reason`/`message`, else `lastFailure` (guarded to be at least as recent as the last event). An older fallback followed by a clean run does not badge.
- Downgrade rule (documented in code, CJK Fallback Contract observability clause): a dimension whose stage carries a fallback badge contributes at `0.9×` its Decision 6 weight; `computeHealthJs` normalises by the adjusted weight sum.
