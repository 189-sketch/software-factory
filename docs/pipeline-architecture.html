High-level overview

六个核心 Agent;Daily loop 是独立轨道
Agent 1 · Triage
Classify & gate
读 issue + comments,产出 ready-to-spec / ready-to-implement / needs-info / wait-to-implement。Freshness hash 在 unchanged 时短路跳过(T8.4)。
Agent 2 · Spec phase
写 → 推 → 合 → 评
SpecAgent → spec-push 外部 op → merge-spec-pr → ReviewSpecAgent(用 R 系列 rubric + LLM)。两套独立预算:typesafe veto ≤2, 连续 RUBRIC_RATCHET_LIMIT 失败直接 hard-throw。
Agent 3 · Implementation
Code · commit · PR
从合并后的 specs/ SPEC 读起,在 factory/<N> 分支上实现。提交前 assertImplementationContract 校验;带 correction 提示词做修正重试。
Agent 4 · Review & Verify
Approve → merge
ReviewPrAgent 输出 verdict。VerifyBehaviorAgent 在 reviewed SHA 上重跑实现阶段的验证命令。auto-merge 关时停在 verified 等待人工合。

03

State machine

label ↔ dispatchStage ↔ Project status — 状态机由 runtime/pipeline-definition.mjs 冻结
Label Dispatch stage Project status Loop target
ready-to-spec spec Ready → In progress Spec phase (≤4 iters)
ready-to-implement implementation Ready → In progress Implementation (+ correction)
review-needed review In review ReviewPr → VerifyBehavior
ready-to-merge verify In review VerifyBehavior → Merge gate
verified merge In review Merge if AUTO_MERGE=1 · else waiting
needs-info triage Backlog Park · re-triage on body/comment change
wait-to-implement triage Backlog Author-defined hold · re-triage on change
changes-requested implementation In progress Back to impl with correction
verify-failed implementation In progress Back to impl · if behaviorVerification.status === "blocked", daemon returns waiting
improve-review-pr improve — (internal) Issue #0 only · 24h cooldown

Issue state.status

持久化在 .factory/issues/<n>.json。每次 transition() 同步 label + project status 后写入。

waiting Label 已同步;若 state.status 是 verify-failed 且 behaviorVerification.status === "blocked",此 tick 直接返回。
in-progress 当前正在 runForIssue() 的某个 dispatch stage 内执行。
failed Pipeline 放弃(FACTORY_MAX_AGENT_FAILURES 超限)。下次触达该 issue 时 orchestrator-reset() 清空,让 router 重新评估。
completed PR 已 merge。state.merged=true,project → Done,labels 清空。
simulated Echo-adapter 模式。daemon 不写真实制品直接返回。

Branch / commit 引用

每个实现绑 4 个 SHA:

specSha 合并后的 spec PR head;实现必须基于此。
implSha factory/<n> 分支上的实现 commit。
reviewedSha / reviewedBaseSha Review 绑 (head, base);不匹配 → 重跑 review。
verifiedSha 在 reviewed commit 上行为验证通过的 SHA。
04

Decision router

每个 action 的阈值在 runtime/decisions.yaml;启动时由 runDecisionsPreCheck() 加载
Action Driver Threshold & drift
freshness.skip Typesafe Noul · freshnessCheck() noul_yes_max=0.20 skip when state hash matches last judgment hash.
失败模式映射到 {skip:false, reason:"freshness_unavailable"},不阻断流水线。
triage.apply_label Typesafe Noul · deriveRouting() 3-band:≥0.85 auto / 0.50–0.85 confirm / <0.50 escalate→needs-info.
confirm 中间档需要人工 "Apply?" 确认;无人值守 daemon 路径下基本不执行 — 实测主要落在 auto / escalate 两端。
review-pr.merge_pr Deterministic from state.review.verdict APPROVE ∧ verified ∧ AUTO_MERGE=1 → merge;否则 hold.
YAML 中 3-band 是 spec 承诺(0.90 / 0.65 / human);当前实现是 verdict 确定性路由,不走 LLM 评分。
supervisor.retry Deterministic · decideRouting() retryable_class_only,按 failure-classifier 的 maxAttempts 决定 abort / needs-info / retry.
schema 名字保留以兼容现有 operator .env;0.3.0 起不再调 LLM。
operator.escalate Composite health band · healthBand() <0.5 alert · 0.5–0.7 banner · >0.7 log_only.
YAML 中 channel:pager / dashboard_banner / log_only 是 spec 契约;权重来自 decisions.yaml 的 composite 段。
05

Failure classifier

每类有独立 retry 预算;预算耗尽 → needs-info 或 hard-fail
POLICY_BLOCK
Max attempts: 0 · Default action: needs-info
Guardrails 拒绝(diff 含密钥、不可逆操作)。按定义就是契约违反,不走 retry loop —— 作者或运维必须介入。
USER_INPUT_REQUIRED
Max attempts: 0 · Default action: needs-info
Agent 自报没有 binding input 就不能继续(开放 spec-review 问题、模糊的验收标准)。
CONTRACT_VIOLATION
Max attempts: 2 · Default action: needs-info
Output contract 检查拒绝 agent 的制品(如 assertImplementationContract、JSON schema verify receipt)。带 correction prompt 重试一次,再拒则交还作者。
AGENT_REASONING
Max attempts: 2 · Default action: needs-info
模型输出未解析到期望结构,或自报 reasoning 失败。correction prompt 重试一次,再失败交还作者。
06

Daily self-improvement loop

独立轨道 · 24h cooldown · PR 需人 review 后才生效
ImproveReviewPrAgent · 写入流程
(1) collectFeedback() 调 scripts/collect-feedback.mjs 收集过去 24h 已合 PR 的人类评论 → corpus.
(2) 模型对 corpus 做 classifications + learnings。
(3) 若 learnings 非空:把 "## Human-reviewed learning proposals" 追加到 .agents/skills/review-pr/SKILL.md,推到 factory/improve-review-pr-<runId>,开 PR。
(4) agent 终止。SKILL.md 修改不会自动生效 — 必须人类 review 并合并 PR 后,review-pr skill 才真的更新。

Durable artifacts

状态机和流水线输出落到磁盘的位置
Path Owner Contents
.factory/issues/<n>.json IssueCheckpointStore 原子状态机检查点:agentMode、stage 时间戳、当前 label、commit 绑定、验收结果。
.factory/state-<n>.json daemon 运行摘要(exitCode、summary、stdout、stderr、workdir)。非零退出留 ERROR pipeline-failed + stderr 尾部。
.factory/traces/ observability 由 appendEvent() 写入的 stage 级 trace 事件。
.factory/daemon.log ConsoleLogger UTC+8 时戳的 INFO / WARN / ERROR 流,每个 issue 一个 child logger 作用域。
.factory/daemon.pid daemon lock 单实例锁。第二个 factory start 在它存在时拒绝启动。
.factory/last-improve-review-pr maybeRunDailyImprovement 上次成功 daily tick 的 ISO 时间戳,强制 24h cooldown。
.factory/daemon-death.json handleFatal / handleShutdown uncaughtException 或 signal 退出时写入的 sidecar;含 reason、uptime、message、stack。
.factory/external-ops/*.json operation-receipts 每个外部 op(spec-push / pr-create / pr-merge / label-sync / issue-comment / project-sync)一条幂等 receipt,失败可重放。
specs/<slug>/{PRODUCT,TECH}.md SpecAgent 通过 spec PR 合到默认分支。ImplementationAgent 必须读这两份。
.agents/skills/review-pr/SKILL.md ImproveReviewPrAgent 仅通过 PR 修改;daemon 不直接覆盖,改完要人 review。
